A Python-automated multiplayer F1 tipping competition that publishes to a static GitHub Pages website.

## Core Design Principle: Raw In, Processed Out

```
┌─────────────────────────────────────────────────────┐
│                                                      │
│  data/raw/           data/overrides/    data/processed/ │
│  Write-once            Manual only      Always derived  │
│  never modified        reversible       Delete & regen  │
│                                                      │
│  *.json (tips)       *.json (corr)    *.json (scored) │
│  *.json (results)                     standings.json  │
│                                                      │
└─────────────────────────────────────────────────────┘
         │                   │              │
         └───────────────────┘              ▼
              Raw data + Overrides →  Processed output
```

If the points system changes or a bug is found in logic, you just **re-run the pipeline** and get correct output. Raw data is never lost.

## The Pipeline (`scripts/pipeline.py`)

```
python scripts/pipeline.py                    # all rounds
python scripts/pipeline.py --round 4          # single round only
python scripts/pipeline.py --round 4 --tip-only  # skip results/scoring
python scripts/pipeline.py --force            # re-fetch even if tips exist
```

### Step-by-Step Flow

```
┌────────────────────────────────────────────────────────────┐
│  Step 1: FETCH TIPS                                       │
│  SurveyMarsClient(authenticate) → SurveyIndex(fetch)      │
│  → TipsParser(fetch_and_save) per survey                  │
│  Output: data/raw/tips/r{N}_{slug}_tips.json              │
├────────────────────────────────────────────────────────────┤
│  Step 2: FETCH RESULTS                                    │
│  ResultsFetcher(round_num, year) → fetch_and_save()       │
│  Output: data/raw/results/r{N}_{slug}_result.json         │
├────────────────────────────────────────────────────────────┤
│  Step 3: SCORE ROUNDS                                     │
│  Scorer(round_num) → score_and_save()                     │
│  Reads: raw tips + raw results + overrides                │
│  Output: data/processed/r{N}_{slug}_scored.json           │
├────────────────────────────────────────────────────────────┤
│  Step 4: AGGREGATE STANDINGS                              │
│  Aggregator() → build_and_save()                          │
│  Reads: all processed scored files                        │
│  Output: data/processed/standings.json                    │
├────────────────────────────────────────────────────────────┤
│  Step 5: BUILD WEBSITE                                    │
│  SiteBuilder() → build_and_save()                         │
│  Reads: standings + all scored files                      │
│  Output: docs/index.html (data block injected)            │
└────────────────────────────────────────────────────────────┘
```

## Module Details

### 1. SurveyMarsClient (`survey_mars.py`)

Handles OAuth2 authentication and API calls to SurveyMars.

```
SurveyMarsClient
    ║
    ╠═ authenticate()
    ║   ├─ Clears old tokens
    ║   └─ POST /oauth/token → access + refresh token
    ║
    ╠═ make_request(method, endpoint, ...)
    ║   ├─ GET/POST to https://api.surveymars.com/v1/...
    ║   ├─ Auto-retries on 429 (rate limit)
    ║   └─ Auto-reauthenticates on token errors
    ║
    ╚═ Base URL: https://api.surveymars.com/v1
       Auth payload: {"id": account_id, "credential": secret}
       Auth header: Authorization: Bearer {access_token}
```

### 2. SurveyIndex (`survey_index.py`)

Fetches all surveys and assigns round numbers by chronological publish order.

```
SurveyIndex(client)
    ║
    ╠═ fetch()
    ║   ├─ GET /surveys?page_size=100
    ║   ├─ Filters out UAT surveys (title contains parentheses)
    ║   ├─ Sorts by time_published ascending
    ║   └─ Assigns round_num = 1, 2, 3...
    ║
    ╠═ all()      → list of all surveys
    ╠═ active()   → only active (open) surveys
    ╠═ closed()   → only closed surveys
    ║
    ╚═ print_summary() → formatted table for debugging
```

### 3. TipsParser (`tips_parser.py`)

Fetches responses for one survey, parses them, saves to raw tips.

```
TipsParser(client)
    ║
    ╠═ fetch_and_save(survey_id, round_num, race_name, force=False)
    ║   ├─ GET /surveys/{id}/responses?page_size=100
    ║   ├─ Normalizes response keys (responses come as dict → extract entry["value"])
    ║   ├─ Detects sprint weekends (question index 60001 present)
    ║   ├─ Saves to data/raw/tips/r{N}_{slug}_tips.json
    ║   └─ Championship predictions saved if present (round 1 only)
    ║
    ╚═ load(round_num, race_name) → load from file without hitting API
```

#### Survey Question Structure

Each SurveyMars survey has three question types identified by `question_index`:

| question_index | Contents |
|---|---|
| `10000` | Player name (single select from list) |
| `20001`–`20010` | Main race picks P1–P10 (individual columns) |
| `20000` | Concatenated top 10 string — **do not use** |
| `60001`–`60003` | Sprint picks S1–S3 (only on sprint weekends) |
| `60000` | Concatenated sprint string — **do not use** |
| `50000` | DNF picks (single code or comma-separated codes) |

#### Raw Tips File Format

```json

  "race_name": "Japan",
  "survey_id": "m1BbiXKjA",
  "is_sprint_weekend": false,
  "fetched_at": "2026-03-27T12:00:00",
  "total_responses": 11,
```

### 4. ResultsFetcher (`fetch_results.py`)

Fetches race results from the OpenF1 API.

```
ResultsFetcher(round_num, year)
    ║
    ╠═ fetch_and_save()
    ║   ├─ Queries OpenF1 for race sessions (practice, qualifying, race, sprint)
    ║   ├─ Extracts: top10, sprint_top3, dnfs, championship_top10_before_race
    ║   ├─ Championship snapshot taken at race time (for underdog bonus)
    ║   └─ Saves to data/raw/results/r{N}_{slug}_result.json
    ║
    ╚═ Import-only — no CLI entry point
```

#### Raw Results File Format

```json

  "round": 3,
  "race_name": "Japan",
  "year": 2026,
  "is_sprint_weekend": false,
  "top10": ["VER","NOR","PIA","LEC","RUS","HAM","SAI","ANT","HAD","ALB"],
  "sprint_top3": null,
  "dnfs": ["STR","GAS"],
  "championship_top10_before_race": [
```

### 4b. ScheduleFetcher (`fetch_schedule.py`)

Fetches the round's full session schedule (start times) from OpenF1 so the
Scorer can detect late submissions offline.

```
ScheduleFetcher(round_num, year)
    ║
    ╠═ fetch_and_save(force=False)
    ║   ├─ Fetch-if-missing (skips network when the file already exists)
    ║   ├─ Resolves meeting_key via get_race_calendar (cancellation-aware renumbering)
    ║   ├─ Saves all sessions (Practice/Qualifying/Sprint/Race) with UTC date_start
    ║   └─ Saves to data/raw/schedule/r{N}_{slug}_schedule.json
    ║
    ╚═ Import-only — no CLI entry point
```

### 5. Scorer (`scorer.py`)

Reads raw tips, raw results, overrides, and the session schedule — applies
scoring rules (including automatic late penalties via
`penalties.assess_lateness()`) — outputs processed scored data.

```
Scorer(round_num)
    ║
    ╠═ score_and_save() → data/processed/r{N}_{slug}_scored.json
    ║   │
    ║   ├── _load_tips()         → from data/raw/tips/
    ║   ├── _load_results()      → from data/raw/results/
    ║   ├── _load_overrides()    → from data/overrides/ (may not exist)
    ║   │
    ║   ├── _score_main_race()   → position matching → result classification
    ║   ├── _score_sprint()      → sprint picks → 5 pts per correct
    ║   ├── _score_dnfs()        → 15 pts per correct DNF pick
    ║   └── _parse_overrides()   → penalty overrides per player
    ║
    └── Scoring logic:
        ┌─────────────────────────────────────────────────┐
        │ For each pick:                                  │
        │   result = position_match(pick, actual_pos)     │
        │   base = {exact:5, close:3, top10:1, miss:0}    │
        │   underdog = (round>1) and driver not in top10  │
        │   points = base * 2 if underdog else base       │
        └─────────────────────────────────────────────────┘
```

#### Scoring Rules

**Main Race:**

| Result | Condition | Base Points |
|---|---|---|
| `exact` | Driver in correct position | 5 |
| `close` | Driver one position away | 3 |
| `top10` | Driver in top 10, wrong spot | 1 |
| `miss` | Driver not in top 10 | 0 |
| `underdog` bonus | Driver outside championship top 10 (excluding round 1) | 2× multiplier |

**Sprint:**

- **5 points** per correct sprint position (P1, P2, P3)
- Only scored on sprint weekends
- Stored separately as `sprint_tips` (not folded into main `scores`)

**DNFs:**

- **15 points** per tipped driver who actually DNFs
- Must have started the race (DNS doesn't count)
- Season budget: **5 picks total** (used across any round)

**Penalties (automatic — `penalties.assess_lateness()`):**

- Detected by comparing `submitted_at` (Australia/Melbourne local time) against
  real session start times from `data/raw/schedule/` (UTC), compared in UTC
- Late: **-5 per penalty session whose start has passed** (basis = session start;
  deadline = Practice 1 start)
- Normal weekend penalty sessions: Practice 1/2/3; cutoff = Qualifying
- Sprint weekend penalty sessions: Practice 1 + Sprint Qualifying; cutoff = Sprint
- After the cutoff has started: **scores zero** (main + DNF)
- Late on a sprint weekend also earns **zero sprint points**
- Automatic penalty **stacks on** any manual override penalty
- Total cannot go negative (floored at 0)

#### Processed Scored File Format

```json
{
  "round": 3,
  "race_name": "Japan",
  "scores": {
    "Luca": 28,
    "Barry": 16
  },
  "player_tips": [
    {
      "player": "Luca",
      "response_id": 7,
      "submitted_at": "2026-03-26T22:32:33",
      "score": 28,
      "penalty": 0,
      "auto_penalty": 0,
      "override_penalty": 0,
      "late_sessions": [],
      "zeroed": false,
      "picks": [
        {"driver": "Russell",  "result": "exact", "underdog": false, "points": 5},
        {"driver": "Leclerc",  "result": "close", "underdog": false, "points": 3}
      ],
      "dnf_picks": [
        {"driver": "Stroll", "dnfd": true,  "points": 15},
        {"driver": "Gasly",  "dnfd": false, "points": 0}
      ]
    }
  ],
  "sprint_tips": [
    {
      "player": "Luca",
      "picks": [
        {"driver": "Verstappen", "result": "miss", "points": 0},
        {"driver": "Piastri",    "result": "miss", "points": 0},
        {"driver": "Norris",     "result": "miss", "points": 0}
      ],
      "score": 0,
      "zeroed": false
    }
  ]
}
```

`penalty` = `auto_penalty` + `override_penalty`. Pick-level `points` stay raw;
the deduction is applied to `score` (floored at 0). A late player's sprint
entry has `zeroed: true` and `score: 0`.

### 6. Aggregator (`aggregator.py`)

Builds season standings from all scored files.

```
Aggregator()
    ║
    ╠═ build_and_save() → data/processed/standings.json
    ║   │
    ║   ├── For each scored file:
    ║   │   └─ For each player: accumulate main race score
    ║   │       └─ If sprint scores exist for same round:
    ║   │           → Merge sprint pts into existing round total
    ║   │
    ║   └─ Sort by total points descending
    ║
    └─ Standing entry per player:
       {
         "name": "Dean",
         "rank": 1,
         "games_played": 3,
         "points": 103,              # total including sprint
         "lastRace": 17,             # last round score
         "bestRound": 58,            # highest single-round score
         "roundScores": {
           "1": {"race": "Melbourne", "points": 28},
           "2": {"race": "China",    "points": 58},  # 53 main + 5 sprint
           "3": {"race": "Japan",    "points": 17}
         }
       }
```

### 7. SiteBuilder (`build_site.py`)

Reads processed data, assembles website data structures, injects into HTML.

```
SiteBuilder()
    ║
    ╠═ build_and_save() → docs/index.html
    ║   │
    ║   ├── _build_players()        → flat list of names
    ║   ├── _build_standings_array() → STANDINGS for JS
    ║   ├── _build_rounds()         → ROUNDS + merged sprint scores
    ║   ├── _build_main_tips()      → MAIN_TIPS
    ║   ├── _build_sprint_tips()    → SPRINT_TIPS (separate array)
    ║   ├── _build_dnf_tips()       → DNF_TIPS (all rounds with DNFs)
    ║   │
    ║   └─ Regex replaces // DATA_START → // DATA_END in HTML
    ║      with serialized JS constants
    ║
    └─ Website structure:
       Leaderboard tab  → standings table (Pts, Gap, Last race, Best round, Avg, DNFs)
       Race Results tab → card per round with top 3 scores
       Charts tab       → cumulative line chart + per-round bar charts
       Tips tab         → Main race + Sprint + DNF sub-tabs
       DNF Tracker tab  → budget pip tracker + per-player card view
```

## The Website (`docs/index.html`)

Single self-contained HTML file. The Python pipeline only touches the data block between `// DATA_START` and `// DATA_END` — the HTML/CSS/JS is never modified.

### Tabs

| Tab | Content |
|---|---|
| **Leaderboard** | Standings table with points, gap to leader (time-tower style), last race score, best round, avg/match. Stat cards show leader, P1→P2 gap, player count, rounds played, last round winner. DNF budget shown as colored pips in rightmost column. |
| **Race Results** | Card per round showing top 3 scores. Expandable to see all players. |
| **Charts** | Cumulative points line chart (per-player toggle buttons) and per-round bar chart. Uses Chart.js from CDN. Cumulative includes "Start" origin at zero. |
| **Tips** | Three sub-tabs: Main race (P1–P10), Sprint (P1–P3), DNFs. Transposed table view on desktop, card-per-player on mobile. |
| **DNF Tracker** | Budget pip tracker grid (who has picks left) + per-race card view on mobile. |

### Mobile Responsive

| Feature | Desktop (>600px) | Mobile (<=600px) | Phones <400px |
|---|---|---|---|
| Tips tables | Transposed table | Card per player | Same card view |
| Cumulative chart | height=100 | height=350 | height=350 |
| Per-round charts | Grouped bar chart | One chart per race (stacked) | Same |
| DNF tracker | Table view | Card per player | Card per player |
| Leaderboard | All 8 columns | 5 cols (#, Player, Pts, Gap, DNF) | 4 cols (Gap hidden) |

### Data Injection

```python
import re, json

# build_site.py replaces everything between these markers:
// DATA_START
const PLAYERS = ["Alice", "Bob", ...];
const STANDINGS = [...];
const ROUNDS = [...];
const MAIN_TIPS = [...];

```

### JavaScript Data Structures

**STANDINGS** — one object per player:
```js
{ name, points, lastRace, bestRound, roundScores: [] }
```

**ROUNDS** — one object per completed race:
```js
{ round, name, date, winner, pole, fastest,
  scores: { "PlayerName": points, ... } }
```

**MAIN_TIPS** — one object per completed race:
```js
{ round, raceName,
  positions: ["Driver",...],   // actual P1–P10
  tips: [
    { player, score,
      picks: [{ driver, result, underdog }, ...] }
  ]
}
```

**SPRINT_TIPS** — same shape as MAIN_TIPS but `positions` is P1–P3 only.

**DNF_TIPS** — one object per round where DNFs occurred:
```js
{ round, raceName,
  actualDnfs: ["Driver",...],
  tips: [
    { player, picks: ["Driver",...], picksUsed, score }
  ]
}
```

## Key Decisions Log

| Decision | Rationale |
|---|---|
| Plain HTML + JS (no framework) | No build step needed; Python generates directly |
| JSON files in Git (not DB) | Zero cost; full version history; re-scoreable anytime |
| Raw/processed separation | Re-scoring without data loss; overrides are traceable |
| One survey per race | Self-maintaining; round order from publish date |
| DATA_START/END markers in HTML | Python only touches data; CSS/JS/HTML untouched |
| No pagination on API | Max 24 surveys × ~15 players — fits in one page |
| Underdog snapshotted at race time | Correct championship standings on re-score |
| DNF budget tracked globally | 5 picks/season, allocatable to any race |
| Sprint scores merged into round totals | `build_site.py` and `aggregator.py` both add sprint pts |
| DNF rounds included even with 0 picks | `_build_dnf_tips()` shows round if there were actual DNFs |
| Website header: "2026 Visa Cash App F1 Tipping Competition" | Centered, no separate season badge |
| Mobile tips use card layout | Tables scroll badly on phones; cards read naturally |
| Chart button toggle via opacity only | No ugly background color flash on toggle |

## Driver Code Normalization

SurveyMars returns 3-letter codes (e.g. `RUS`, `NOR`, `LEC`). These are normalized to full surnames via `DRIVER_MAP` in `race_utils.py`. New drivers/variants must be added as discovered.

```python
DRIVER_MAP = {
    "RUS": "Russell",
    "NOR": "Norris",
    "VER": "Verstappen",
    # ... etc
}
```

At scoring time, `race_utils.py` also provides `clean_race_name()` which strips "GP"/"Grand Prix" from circuit names for consistent filenames and display.

## Override System

Late penalties are applied automatically (see the Penalties section). Overrides
remain for manual corrections the automatic detection can't make, and **stack on
top of** the automatic penalty.

```json
// data/overrides/r02_china_overrides.json
{
  "round": 2,
  "note": "Manual adjustment on top of any automatic penalty",
  "overrides": [
    {
      "player": "Player X",
      "penalty_points": 5,
      "reason": "manual_correction"
    }
  ]
}
```

- Only created when a manual correction is needed
- Separate from raw data so corrections are visible and reversible
- Applied during scoring via `Scorer._parse_overrides()`
- `penalty = auto_penalty + override_penalty`, applied after main race + DNF
  scores are calculated, before flooring at 0
