# F1 Tipping Competition — Project Reference

This document captures all key decisions, architecture, data structures, and code conventions established during planning. Use it as the source of truth when building new components.

---

## Project Goal

Fully automate a multiplayer F1 tipping competition. Players submit tips via SurveyMars before each race. A Python pipeline scores them against real results from the OpenF1 API and publishes a static leaderboard website to GitHub Pages — all updating automatically each race weekend with no manual work.

## Core Design Principle: Raw In, Processed Out

- `/data/raw/` is **write-once**. The pipeline writes files here once and never modifies them.
- `/data/processed/` is **always derived**. Delete and regenerate at any time by re-running the pipeline against raw files.
- `/data/overrides/` holds manual corrections (e.g. late submission penalties) kept separate from raw data so corrections are visible and reversible.

This means if the points system changes, or a bug is found in scoring logic, you just re-run the pipeline and get correct output. Raw data is never lost.

## Scoring Rules

### Main Race
- **5 points** — driver picked in the correct position (exact)
- **3 points** — driver picked one position away from their actual position (close)
- **1 point** — driver picked anywhere else in the top 10 (top10)
- **0 points** — driver not in the top 10 (miss)
- **Underdog bonus** — any driver outside the championship top 10 before the race scores **double points** (excluding round 1)
- Late submission penalty: **-5 points per missed practice session**
- Submission after qualifying: **scores zero**
- Total points for a race weekend **cannot go negative**

### Sprint
- **5 points** for each driver selected in the correct position (P1, P2, P3)
- Only scored on sprint weekends
- Late submissions on a sprint weekend **cannot earn sprint points**; the sprint takes the place of qualifying for penalty purposes

### DNFs
- **15 points** if a tipped driver actually DNFs in that specific race
- The driver must have **started the race** to count
- Each player has a **season budget of 5 DNF picks total** across all rounds
- Players can use 0–5 picks per round as long as the season total does not exceed 5

## Tip Collection — SurveyMars

### Setup
- A **new survey is created for each race weekend** in SurveyMars
- Surveys are fetched via the SurveyMars Open API
- The pipeline determines round order by sorting surveys by `time_published` (oldest first)
- UAT/test surveys must be filtered out (any title containing parentheses e.g. `"Las Vegas GP (UAT)"`)

### Survey Question Structure
Each survey has three question types identified by `question_index`:

| question_index | Contents |
|---|---|
| `10000` | Player name (single select from list) |
| `20001`–`20010` | Main race picks P1–P10 (individual columns) |
| `20000` | Concatenated top 10 string — **do not use**, use individual columns |
| `60001`–`60003` | Sprint picks S1–S3 (only on sprint weekends) |
| `60000` | Concatenated sprint string — **do not use** |
| `50000` | DNF picks (single code or comma-separated codes) |

### Driver Codes
SurveyMars returns 3-letter driver codes (e.g. `RUS`, `NOR`, `LEC`). These are normalised to full surnames via `DRIVER_MAP` in `TipsParser`. The full map is maintained in `tips_parser.py` — add new drivers/variants as discovered.

### Raw Tips File Format
Saved to `data/raw/tips/r{round:02d}_{race_slug}_tips.json`:

- `race_name` stores just the circuit name (e.g. `"Melbourne"`, not `"Melbourne GP"`)
- Driver picks are stored as **raw 3-letter codes** (e.g. `"NOR"`, `"LEC"`) — normalised to surnames at **scoring time**
- `dnf_picks` is a list of 3-letter codes, split on `","` or `"┋"` (U+250B)

```json
{
  "round": 3,
  "race_name": "Japan",
  "survey_id": "m1BbiXKjA",
  "is_sprint_weekend": false,
  "fetched_at": "2026-03-27T12:00:00",
  "total_responses": 11,
  "submissions": [
    {
      "player": "Luca",
      "response_id": 7,
      "submitted_at": "2026-03-26T22:32:33",
      "time_spent_s": 154,
      "main_race": ["RUS","LEC","HAM","ANT","PIA",
                    "BEA","HAD","NOR","SAI","LAW"],
      "sprint": null,
      "dnf_picks": ["ALO","STR"]
    }
  ]
}
```

Race names in both JSON and filenames **do not** include "GP" or "Grand Prix" suffixes — just the circuit name (e.g. `r01_melbourne_tips.json`, `"race_name": "Melbourne"`).

### Sprint Detection
Sprint weekends are **auto-detected** by checking for the presence of sprint question index `60001` in the response data. No manual flag needed.

- `TipsParser._is_sprint_weekend(raw_responses)` — checks first response for question `60001`
- `fetch_and_save()` no longer accepts an `is_sprint` parameter

### Championship Predictions
Saved to `data/raw/tips/championship_predictions.json` (only for round 1):

```json
{
  "round": 1,
  "race_name": "Melbourne",
  "survey_id": "7UogehrrK",
  "predictions": [
    {
      "player": "Antonio",
      "drivers_pick": "RUS",
      "constructors_pick": "Mercedes"
    }
  ]
}
```

- Question index `30000` → drivers championship
- Question index `40000` → constructors championship
- Detected when present in responses — only expected in round 1

## Race Results — OpenF1

### Raw Results File Format
Saved to `data/raw/results/r{round:02d}_{race_slug}_result.json`:

- Uses **3-letter codes** throughout (matching tips format)
- `race_name` is just the circuit name (e.g. `"Melbourne"`)
- `dnfs` are drivers where `dnf: true` (started but didn't finish — not DNS)
- Sprint is detected by whether `ResultAggregator` has a sprint session

```json
{
  "round": 3,
  "race_name": "Japan",
  "year": 2026,
  "is_sprint_weekend": false,
  "top10": ["VER","NOR","PIA","LEC","RUS","HAM","SAI","ANT","HAD","ALB"],
  "sprint_top3": null,
  "dnfs": ["STR","GAS"],
  "championship_top10_before_race": [
    "NOR","PIA","RUS","LEC","HAM","VER","SAI","ANT","ALO","HAD"
  ]
}
```

`championship_top10_before_race` must be **snapshotted at race time** so the underdog bonus is always calculated correctly even when re-scoring later.

### `ResultsFetcher` (`fetch_results.py`)
- `__init__(round_num, year, output_dir)` — creates `ResultAggregator` and resolves race name from OpenF1 calendar (`circuit_short_name`)
- `fetch_and_save()` — extracts top10, dnfs, championship top10, sprint top3 and writes to raw JSON
- `fetch_results.py` is **import-only** — no CLI entry point

## Processed Scored File Format
Saved to `data/processed/r{round:02d}_{race_slug}_scored.json`:

```json
{
  "round": 3,
  "race_name": "Japan GP",
  "scores": {
    "Luca": 28,
    "Barry": 16
  },
  "player_tips": [
    {
      "player": "Luca",
      "score": 28,
      "penalty": 0,
      "picks": [
        {"driver": "Russell",  "result": "exact", "underdog": false, "points": 5},
        {"driver": "Leclerc",  "result": "close", "underdog": false, "points": 3}
      ],
      "dnf_picks": [
        {"driver": "Stroll", "dnfd": true,  "points": 15},
        {"driver": "Gasly",  "dnfd": false, "points": 0}
      ]
    }
  ]
}
```

The `result` field on each pick is one of: `"exact"`, `"close"`, `"top10"`, `"miss"`.

## Website — `docs/index.html`

Single self-contained HTML file generated by `build_site.py`. Served free via GitHub Pages from the `docs/` folder on the `main` branch.

### Tabs
1. **Leaderboard** — standings table with points, last race score, best round, avg per race. Stat cards show leader, P1→P2 gap, player count, rounds played, last round winner.
2. **Race Results** — card per round showing winner, pole, fastest lap, and top 3 scores (expandable to all players).
3. **Charts** — cumulative points line chart (with per-player toggle buttons) and per-round bar chart. Both use Chart.js loaded from CDN.
   - Cumulative chart includes a "Start" label at zero so all lines begin from a common origin
   - Toggle buttons use `opacity` only to dim hidden players — no background color change
4. **Tips** — three sub-tabs:
   - **Main Race** — transposed table (positions as columns, players as rows) with colour-coded cells and underdog stars
   - **Sprint** — same layout, P1–P3 only, only shown on sprint weekends
   - **DNFs** — season budget pip tracker per player + per-round picks table

### Mobile Responsive
- Below 600px the wide tips tables are replaced with vertical card layout (one card per player)
- CSS `.tips-cards` containers are populated by `renderTipsCard()` helper — hidden on desktop via `display:none`, shown on mobile via media query
- The table view (`.tips-table-scroll`) is hidden on mobile in favour of the card view

### Data Injection
The `build_site.py` script replaces everything between `// DATA_START` and `// DATA_END` in `index.html` using a regex replace. The HTML/CSS/JS is never touched by the pipeline — only the data block is swapped out.

```python
import re, json

new_data = f"""
const PLAYERS = {json.dumps(players)};
const STANDINGS = {json.dumps(standings)};
const ROUNDS = {json.dumps(rounds)};
const MAIN_TIPS = {json.dumps(main_tips)};
const SPRINT_TIPS = {json.dumps(sprint_tips)};
const DNF_TIPS = {json.dumps(dnf_tips)};
"""

html = re.sub(
    r'// DATA_START.*?// DATA_END',
    f'// DATA_START\n{new_data}\n// DATA_END',
    html,
    flags=re.DOTALL
)
```

### JavaScript Data Structures

**STANDINGS** — one object per player:
```js
{ name, points, lastRace, bestRound, roundScores: [] }
```

**ROUNDS** — one object per completed race:
```js
{ round, name, date, winner, pole, fastest,
  scores: { "PlayerName": points, ... } }
```

**MAIN_TIPS** — one object per completed race:
```js
{ round, raceName,
  positions: ["Driver",...],   // actual P1–P10
  tips: [
    { player, score,
      picks: [{ driver, result, underdog }, ...] }
  ]
}
```

**SPRINT_TIPS** — same shape as MAIN_TIPS but `positions` is P1–P3 only.

**DNF_TIPS** — one object per round where picks were made:
```js
{ round, raceName,
  actualDnfs: ["Driver",...],
  tips: [
    { player, picks: ["Driver",...], picksUsed, score }
  ]
}
```

### Cell colour coding in the website tips table
- 🟢 **Green** (`exact`) — correct position, 5 pts base
- 🟡 **Amber** (`close`) — one position off, 3 pts base
- 🔵 **Blue** (`top10`) — in top 10, wrong position, 1 pt base
- ⬜ **Grey** (`miss`) — not in top 10, 0 pts
- ⭐ **Pink star** — underdog bonus (2×), shown only when the selection actually earned points (not for "miss" results)

### DNF Tracker
- All rounds with actual DNFs appear in `DNF_TIPS`, even if no player made picks
- `_build_dnf_tips()` in `build_site.py` includes rounds with zero picks so the website shows the actual DNF list

### Website Header
- Header text: "2026 Visa Cash App F1 Tipping Competition", centered
- No separate season badge — "2026" is part of the title

## Python Classes

### `SurveyMarsClient` (`scripts/surveymars_client.py`)
Handles OAuth2 authentication and all raw API calls to SurveyMars.

- `authenticate()` — gets fresh access + refresh tokens using account ID and secret. Clears existing tokens first.
- `make_request(method, endpoint, params, json_data)` — authenticated request helper. Auto-retries on 429 (rate limit). Auto-reauthenticates on token errors (codes 2004, 2005).
- Base URL: `https://api.surveymars.com/v1`
- Auth payload: `{ "id": account_id, "credential": secret }`
- Auth header: `Authorization: Bearer {access_token}`

### `SurveyIndex` (`scripts/survey_index.py`)
Fetches all surveys and assigns round numbers by chronological publish order.

- `fetch()` — single API call to `GET /surveys?page_size=100`, sorts by `time_published` ascending, assigns round numbers 1, 2, 3...
- Filters out UAT/test surveys (titles containing parentheses)
- `all()` / `active()` / `closed()` — filtered views
- `print_summary()` — formatted table for debugging
- **Note:** API response structure is `{ has_next, data: [...surveys] }` — the list is at `response["data"]`

### `TipsParser` (`scripts/tips_parser.py`)
Fetches responses for one survey, parses them, and saves to `/data/raw/tips/`.

- `fetch_and_save(survey_id, round_num, race_name, is_sprint, force)` — main entry point
- `load(round_num, race_name)` — load a previously saved file without hitting the API
- Single request to `GET /surveys/{survey_id}/responses?page_size=100` — no pagination needed
- **Note:** Responses come back as a dict keyed by response_id; the actual response object is at `entry["value"]`
- Sprint question indices: `60001`, `60002`, `60003`
- DNF answer is a single code or comma-separated string; `"(Empty)"` means no picks

### `build_site.py`
Reads all processed scored files and standings, assembles website data, injects into `index.html`.

### Python Classes — Completed
The following modules previously marked as TODO have been implemented:

- `aggregate.py` — reads all processed scored files, builds `standings.json`

## Key Decisions Log

| Decision | Rationale |
|---|---|
| Plain HTML + JS for website (not Next.js/Nuxt/Astro) | No build step needed; Python generates the file directly; frameworks solve problems this project doesn't have |
| CSV/JSON files committed to Git (not a database) | Zero cost; Git provides version history and audit log; re-scoreable at any time |
| Raw/processed separation | Enables re-scoring without data loss; overrides are traceable |
| One survey per race in SurveyMars | Simpler than one survey per season; round order derived from publish date |
| Round numbers assigned by publish date sort | No hardcoded config; self-maintaining as new surveys are created |
| Single `index.html` with DATA_START/END markers | Pipeline only touches the data block; HTML/CSS/JS never modified by automation |
| No pagination on SurveyMars API calls | Max 24 surveys per season, max ~15 players — always fits in one page |
| Sprint question indices `60001`–`60003` | Confirmed from real China GP sprint response data |
| Underdog bonus snapshotted at race time | Ensures re-scoring always uses the correct championship standings |
| DNF budget tracked as running total across rounds | 5 picks per season, allocatable to any race in any quantity |
